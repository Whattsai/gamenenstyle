## 功能概述

本分項為整個雨聲書店 V4 的地基工作包，負責將唯一文案與劇本權威 `docs/requirements/rain-bookshop-v4-draft.json`（保持原檔一字不動）轉化為受嚴格型別與安全護欄保護的 `scene-event.v3` 正式四層內容契約（`scene`、`narrative`、`pool`、`definitions`）與 80 項經解碼及權利核驗的正式素材，並提供機器可執行的逐 JSON path／Unicode scalar 原稿完整性驗證器、有界商狀態可達性驗證器（保留 `50,000` state guard）、可配置 `durationSeconds`（初版 90 秒，並支援 120 秒合法測試版）門檻一致性檢查器，以及不覆寫舊版 V3 SHA 的不可變發布管線。

- **沿用理由**：沿用既有 `cloudflare/src/scene-event-*-content.ts` 的 Zod 嚴格白名單架構、`scene-event-track-graph.ts` 的雙角色 BFS 框架與 `tools/scene-event-publish-policy.mjs` 的內容定址 R2 + D1 Catalog 發布機制，保留 `scene-event.v2` 相容讀取至 Gate B 後清理。
- **新增與調整理由**：V3 硬編碼 `scene-event.v2`、speaker 僅有 `旁白`／`店員・NPC`、無多區 20 書／盲書／共享模組／可配置倒數結構，且直接展開可重複彩蛋會超過 `50,000` 狀態上限，故必須擴充版本化 `v3` schema、有界可達性折疊與 V4 專屬原稿編譯校驗器。
- **明確排除**：本包不修改 `.NET` 領域／應用層執行期邏輯（歸 [SD-002](SD-002-雙軌破冰與限時救書領域規則.md)、[SD-003](SD-003-權威計時交易與房間排程同步.md)）、不修改前端 React Native 元件（歸 [SD-004](SD-004-去按鈕化探索書牆與雙向破冰前端UX.md)、[SD-005](SD-005-暴雨救書協作與四結局借閱小票前端UX.md)），亦不在 Gate B 前刪除既有 V3 內容檔案（歸 [SD-007](SD-007-實玩GateB與Local清理結案交付.md)）。

## 用戶故事

- 作為**配對進入雨聲書店的兩名玩家**，我想要在書店五個角落讀到原汁原味、零版權疑慮的 16 本經典自譯與 4 本神秘盲書，並在所有路線（含慢熟獨處、反向搭話與限時救書）都不會遇到卡死、缺圖或被縮減的假文案，以便沉浸體驗完整的互動故事。
- 作為**平台維運與內容發布者**，我想要由編譯與發布管線自動強制驗證原稿逐字完整性、時間門檻合理性、有界可達性與不可變 SHA 升版，以便在不影響既有場次且不放寬安全護欄的前提下安全交付 V4。

## 畫面操作／系統處理流程

本包為離線內容編譯、契約解析與不可變發布管線，無直接客戶端畫面寫入；其處理流程如下：
1. **唯讀載入與指紋鎖定**：讀取 `docs/requirements/rain-bookshop-v4-draft.json`，先驗原檔 SHA-256 必等於 `b5c18f6762c87e25e1e83deb5769d19dc170c94a69bd6c1cdb15fe34b6809d95`（不匹配立即中止）。
2. **素材與權利前置驗證**：依 `scene.assetManifestPlan`（80 項）逐一讀取 18 項 V3 既有資產與 62 項 V4 新增資產，驗證 PNG/WebP 影像寬高、非全透明遮罩 `hitMask`、WAV PCM/RIFF 標頭、`byteLength <= 8,388,608`、計算真實 SHA-256，並核對 16 本經典逐書法域／原作與原創自譯、封面及音樂的權利證據表。
3. **無損編譯與興趣代碼映射**：產生 `scene-event.v3` 四層結構，保留全部原始文案與 ID，附加可逆技術 binding ID、6 個受控樣板 token 標記、20 本書 `authorInterestTags` 至 `ProfileCatalog` 正式代碼映射表，以及 `durationSeconds`／水位廣播／`S_fast` 設定。
4. **雙向逐字對照與有界可達性閘門**：執行 `verifyDraftScalarIntegrity` 確認無任何文字被 trim 或改動；執行 `validateTrackV3Reachability` 在 `50,000` 狀態護欄內確認 28 節點、兩題組、問答、拒絕與 4 結局全可達且零死鎖，並量測最壞執行期 JSON 長度 `< 16,384`。
5. **不可變發布與雙版本並存**：寫入 `contracts/rain-bookshop-v4.json` 與更新 `contracts/scene-event-content.json` 新配對首場指向；發布至本地 R2/D1 時僅新增不可變 SHA 物件與新版本列，保留既有 V3 SHA 供舊場次透過 `scene-event.v2` 讀取，直到 Gate B 核准後由 `SD-007` 清理。

### 畫面、元件與互動分解（適用時）

本包不直接修改 `frontend/client/` 畫面元件（不適用直接 UI 程式碼寫入）；但本包產出的 `contracts/rain-bookshop-v4.json` 直接提供 [SD-004](SD-004-去按鈕化探索書牆與雙向破冰前端UX.md) 與 [SD-005](SD-005-暴雨救書協作與四結局借閱小票前端UX.md) 所需的 8 個 `areas` 鄰接圖、8 組 `cameras` 參數、80 項資產 SHA 與 `bounds`/`hitMask`、20 本書完整欄位、7 個共享模組文案與 14 組 `uiCopy`，確保前端零硬編碼劇本文字。

### 契約、資料與平台

- **Schema 版本**：新增 `scene-event.v3`，完整保留 `scene-event.v2`。
- **分類與興趣代碼對齊**：在 `tools/scene-event-publish-policy.mjs` 的分類集合擴充 `'healing'`（連同既有 `'romance'` 等），書籍 `matchedProfileCodes` 只對應 `ProfileCatalog.cs` 既有 interestTagIds，不跨 topic/value；無對應保留原作者標籤而不猜測，零新增資料庫代碼。
- **Migration／回填／Rollback**：無 DB schema migration；發布至 R2/D1 為純附加不可變 SHA，回退只需切換預設首場指標。

### 共用與改動合理性

- 將 V4 專屬原稿結構與權利校驗獨立於 `tools/rain-bookshop-v4-policy.mjs`，不污染通用 `scene-event-content-policy.mjs`，也不在 Gate B 前觸碰 `tools/rain-bookshop-v3-policy.mjs`，確保既有 `check:foundation` 內的 V3 測試 100% 綠燈通過。
- 允許實作自行決定的局部細節：62 項新增 PNG/WebP 與 WAV 素材在符合原稿視覺／聽覺描述、單檔 `<= 8MiB` 與精確區域 `bounds`/`hitMask` 前提下的具體繪製筆觸與合成參數，以及內部私有輔助函式命名。

### 興趣貼紙原稿相容規則

- 以本人已儲存 interestTagIds 為推薦依據。原稿 selfMatchLabel、sharedPublicMatchLabel 均須原樣保留；預設只使用 selfMatchLabel。僅雙方明確公開且兩人的實際同一興趣代碼與該書映射交集非空，才可使用 sharedPublicMatchLabel；否則不讀取／暴露他方未公開興趣，不返回任何他方原始興趣集合。
- family、music、photography 無完全對應的現行 interestTagIds，保留作者標籤，不以其他類型代碼臆造命中。精確對照提案隨 final 核准，不改 ProfileCatalog。
