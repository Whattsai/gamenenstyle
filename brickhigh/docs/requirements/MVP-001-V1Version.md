# MVP-001: V1Version — 共用積木、人物與道具收藏屋

**功能 ID**: `MVP-001`
**優先級**: 高
**狀態**: MVP 規劃基線已確認；第一份 SPEC 細部規劃中
**最後更新**: 2026-09-08
**本輪階段**: `perfect-plan` Phase 2；本輪僅處理 `SPEC-001-BrickModelCatalog`

## 需求概述

brickhigh 是一款享受樂高自由的3d畫面開放式自由地圖遊戲，運用擁有的樂高，參與各式各樣不同的遊戲

第一版建立後續遊戲可共用的積木模型庫、人物管理及玩家道具收藏屋，完成新手建置後才可進入遊戲。以下保留原始需求，並補充使用者已確認的範圍、可追溯的驗收條件及待確認規劃。

## 主要需求

### 核心功能（原始需求）

第一版預計初始化，涵蓋以下模組需求：

未來需可共用：
1. 樂高積木建模：
- 請先找出樂高釋出的**所有積木模塊**，實際建立模型
- 未來可持續建立樂高新推出的積木貨號

2. 人物建置與管理：人物道具的模型分成-基本款/進階款/特殊款
- 依據建模結果，玩家初次進入系統可以選擇基本款 頭/身體/手/腳/頭飾/手上裝備 各一個，讓玩家建立專屬人物
- 依據建模結果，玩家初次進入系統即可以半價付費購買進階款 頭/身體/手/腳/配飾
- 玩家手上會拿著一個初始時系統發放的積木桶，隨機從模型庫取2026片，作為道具收藏屋的初始道具庫
- 特殊款是透過特殊的樂高聯名款/遊戲成就/活動才可以獲得的積木組件，並不會在人物建置階段出現
- 具備建立多個人物的功能，但需要經由付費或活動發放時，才能另外建立人物，每次建立人物都重用初次進入系統的人物建立流程與相關條件
- 玩家具備多個人物時，進入遊戲需選擇該次遊玩要使用的人物
- 遊戲的成就是與該人物關聯，而不是直接與玩家關聯

3. 道具收藏屋：收藏所有建模的積木，取得來源都是從遊戲/活動/購買...等等方式獲得
- 完成人物建立後，需引導玩家建立道具收藏屋，如果玩家還沒建立收藏屋，手上會一直提著初始積木桶，此時不能進入遊戲，必須先拿積木桶的積木蓋出專屬自己的道具收藏屋，剩下的積木會在蓋好後放進收藏屋儲存，可以隨時回到收藏屋使用
- 道具收藏屋也可以隨時改變樣子，調整過的積木在每次調整後，都會更新回收藏屋中
- 道具是與玩家關聯，可以給不同人物或遊戲使用
- 可以隨時回來編輯人物，並擁有個人的存放櫃，存放櫃的樂高組件需要另外獲得，而不是直接把所有建模的樂高呈現出來

以上完成才可進入遊戲，遊戲會存取人物/道具進行遊戲本身的初始，不過與本階段較無關聯，不在此文件多加贅述。

| `REQ-001` | 所有積木模塊實際建模 | 依 `DEC-001` 建立可核對的未停產積木清單及實際模型；僅有目錄紀錄不算模型完成。 |

| `REQ-004` | 進階款半價購買 | 人物建立流程提供頭、身體、手、腳、配飾的半價購買，依 `DEC-002` 驗收。 |

| `REQ-010` | 未建收藏屋不得進入遊戲 | 人物建立後引導建屋；未完成時保持提桶狀態並禁止進入遊戲。 |
| `REQ-011` | 使用桶中積木建屋及儲存餘料 | 使用初始積木建造收藏屋，完成後剩餘積木存入收藏屋且可再次取用。 |

| `REQ-014` | 編輯人物及個人存放櫃 | 可回來編輯人物，存放櫃呈現實際取得的組件，不因模型存在而自動取得。 |
| `REQ-015` | 完成後才可進入遊戲 | 向遊戲提供符合進入條件的所選人物與玩家道具；遊戲玩法不在本 MVP 範圍。 |

模型目錄代表系統支援的零件；玩家庫存代表玩家已取得的零件與數量；人物裝備與收藏屋建築代表零件的使用位置。成就與人物關聯，道具所有權與玩家關聯。上述區分用於落實原始需求，資料表、API 及同時使用的限制留待各 SPEC 設計。

## 用戶故事與驗收標準

以下條件由原始需求與已確認決策推導，包含「已確認規劃」的 `PLAN-001` 至 `PLAN-003`。抽樣演算法、建屋尺寸與判定細節由對應 SPEC 定義。

### 001：建立與擴充積木模型庫

**身為** 模型維護者，**我想要** 建立範圍內的所有積木模型並持續新增貨號，**以便** 人物、收藏屋及後續遊戲共用。

**需求來源**：`REQ-001`、`REQ-002`、`DEC-001`。

**驗收標準**：

- 有可核對的目錄基準與貨號清單；已停產項目不計入本版需建模範圍。
- 範圍內每個項目皆能對應可載入、可在 3D 場景呈現的模型；只有名稱、圖片或未完成占位模型不算完成。
- 可新增樂高新推出的積木貨號及模型，並由後續共用模組取得。
- 模型完成度以確認後的目錄為分母逐項核對，不以少數示範模型代表全量完成。

### 002：選擇基本款建立人物

**身為** 初次建立人物的玩家，**我想要** 自選各部位基本款，**以便** 建立專屬人物。

**需求來源**：`REQ-003`、`REQ-006`。

**驗收標準**：

- 可從基本款頭、身體、手、腳、頭飾、手上裝備各選一個，建成的人物呈現所選組合。
- 模型可區分基本款、進階款及特殊款。
- 特殊款不出現在人物建立的可選項目中。

### 003：半價購買進階款

**身為** 建立人物的玩家，**我想要** 半價購買進階款，**以便** 搭配進階造型。

**需求來源**：`REQ-004`、`DEC-002`。

**驗收標準**：

- 建立人物時可購買進階款頭、身體、手、腳、配飾；價格可相對商品原價核對為半價。
- 模擬購買成功後，所購組件實際加入玩家可用道具，並可在適用部位使用。
- 驗收走完商品選擇、價格確認、訂單建立、模擬付款結果、發放及結果顯示，不以單一成功提示取代流程。

### 004：取得初始積木桶

**身為** 完成人物建立的玩家，**我想要** 取得初始積木桶，**以便** 使用桶內積木開始建置收藏屋。

**需求來源**：`REQ-005`、`REQ-010`、`REQ-011`。

**驗收標準**：

- 初始積木桶內隨機取得的積木總數恰為 2026 片；「片數」不等於不同貨號數量。
- 未完成收藏屋時，人物保持提桶狀態並被引導建屋。
- 桶內積木可實際用於收藏屋建造。
- 依 `PLAN-001`，允許同款重複、排除特殊款，保證符合建屋完成條件的必要建材，其餘隨機，總量仍恰為 2026 片。

### 005：取得額外人物並重用建立流程

**身為** 想建立多個人物的玩家，**我想要** 經由購買或活動取得額外建立資格，**以便** 建立另一個人物。

**需求來源**：`REQ-007`、`DEC-002`。

**驗收標準**：

- 未取得額外建立資格時，不可建立額外人物。
- 模擬購買成功或活動發放資格後，可進入額外人物建立流程。
- 每次建立人物都重用初次的人物建立流程及相關條件；領桶與已有收藏屋的銜接見 `PLAN-002`。
- 每個新人物皆享建立期半價與一桶 2026 片；玩家已有共用收藏屋時，新桶直接存入收藏屋，不需重新建屋。
- 玩家可保存多個不同人物，並在後續進入遊戲時選擇。

### 006：選擇人物並保留獨立成就

**身為** 擁有多個人物的玩家，**我想要** 選擇本次遊玩人物，**以便** 以該人物累積成就。

**需求來源**：`REQ-008`、`REQ-009`。

**驗收標準**：

- 有多個人物時，進入遊戲前必須完成本次人物選擇。
- 成就紀錄可識別所屬人物；同帳下另一人物不因切換而繼承該人物成就。
- 本版驗收人物歸屬與存取邊界；各遊戲實際成就條件由後續遊戲規格定義。

### 007：建造收藏屋並解鎖遊戲入口

**身為** 尚無收藏屋的玩家，**我想要** 用初始積木建屋並存放餘料，**以便** 完成準備後進入遊戲。

**需求來源**：`REQ-010`、`REQ-011`、`REQ-015`。

**驗收標準**：

- 完成人物建立後引導建置收藏屋，未完成收藏屋時不可進入遊戲。
- 建屋使用桶中實際擁有的積木，完成後剩餘積木進入收藏屋庫存。
- 完成收藏屋且選定可用人物後，遊戲入口能取得該人物及玩家道具資訊。
- 依已確認的 `PLAN-003`，收藏屋至少有相連結構、地板、牆面、出入口及屋頂；檢查方式、尺寸與容許誤差由收藏屋 SPEC 定義。

### 008：修改收藏屋與取用共用道具

**身為** 已有收藏屋的玩家，**我想要** 隨時修改外觀及取用積木，**以便** 持續創作並在不同人物或遊戲使用道具。

**需求來源**：`REQ-012`、`REQ-013`。

**驗收標準**：

- 玩家可回到收藏屋修改積木組成，完成調整後顯示修改後外觀。
- 增加及拆回的積木同步反映於使用量與存放量，不能因編輯而憑空增加或遺失。
- 庫存歸屬玩家，切換人物後仍可存取同一玩家已取得的道具。
- 後續遊戲可透過共用邊界存取道具；實際遊戲內的使用方式另立規格。

### 009：編輯人物與使用存放櫃

**身為** 已建立人物的玩家，**我想要** 回來編輯人物並存放取得的組件，**以便** 更換造型。

**需求來源**：`REQ-006`、`REQ-014`。

**驗收標準**：

- 可回到收藏屋開啟人物編輯，使用已取得的適用組件修改人物。
- 個人存放櫃中的可用組件須有取得紀錄，未取得的模型不會自動出現在可用庫存中。
- 特殊款保留其限定取得來源；本版不擴增聯名活動內容或遊戲成就玩法。

## 模擬購買的驗收範圍

`DEC-002` 確認以模擬付款驗收完整應用流程。下列為對此決策的測試規劃，由對應 SPEC 定義狀態、介面及錯誤處理細節：

| 情境 | 預期驗收結果 |
|---|---|
| 購買進階組件成功 | 依建立人物優惠計算金額，建立訂單，模擬付款成功後發放所購組件，玩家可在適用部位使用。 |
| 購買額外人物資格成功 | 訂單成功後取得額外建立資格，完成建立人物後能在人物清單選用。 |
| 付款失敗或取消 | 保留可辨識的訂單結果，不發放道具或人物資格，玩家能返回流程。 |
| 重複提交或重複收到成功結果 | 同一筆訂單只發放一次，不重複增加道具或人物資格。 |
| 成功後中斷再返回 | 已完成的訂單與已發放結果可重新讀取，不需以再次購買才能取得。 |
| 發放階段失敗 | 不呈現全部完成；重試或恢復後只完成該訂單應發放的一份結果。 |

商品原價、幣別、半價計算與取整、優惠適用次數、人物資格消耗時機由購買及人物 SPEC 細化。第一版不包含實際收款、正式金流服務及真實退款；未來若要啟用，需另行規劃並驗收。

## 畫面操作流程

### 1. 人物建立與首次收藏屋建置

```text
玩家進入系統
  ↓
首次建立人物／持有額外人物建立資格
  ↓
選擇基本款頭、身體、手、腳、頭飾、手上裝備
  ├─ 選購進階款 → 確認半價 → 建立訂單 → 模擬付款 → 發放／顯示未成功結果
  └─ 保留基本款
  ↓
完成人物建立 → 領取初始積木桶
  ↓
尚未建立收藏屋：提桶、禁止進入遊戲 → 使用桶內積木建屋
  ↓
收藏屋通過完成判定 → 剩餘積木存入收藏屋
  ↓
選定本次人物 → 遊戲入口取得人物及道具 → 交由後續遊戲
```

依已確認的 `PLAN-002`，已有收藏屋時建立新人物仍享半價及領桶，桶內 2026 片直接存入玩家共用收藏屋，不重走建屋流程。

### 2. 回到收藏屋

```text
玩家回到收藏屋
  ├─ 修改收藏屋 → 使用／拆回積木 → 保存外觀與庫存變動
  ├─ 開啟存放櫃 → 選擇已取得組件 → 編輯並保存人物
  └─ 取用已取得道具 → 供人物／後續遊戲使用
```

### 3. 額外人物資格與人物切換

```text
玩家選擇新增人物
  ├─ 無資格 → 模擬購買成功或活動發放 → 取得資格
  └─ 已有資格
  ↓
重用人物建立流程 → 完成建立 → 保存至人物清單
  ↓
進入遊戲前選擇本次人物 → 以該人物關聯成就
```

### 4. 模型維護流程

```text
建立範圍與日期明確的零件清單 → 核對停產狀態
  ↓
逐項建立與驗證 3D 模型 → 關聯貨號與變體 → 供共用模組載入
  ↓
發現新貨號 → 加入清單與建模流程 → 更新目錄版本
```

此為維護流程，不預先要求另建模型後台 UI。

## 影響範圍與初步技術規劃

- 模型資產：需有模型目錄、貨號對照、外觀變體及可載入的 3D 資產；角色組件須能對應適用部位。
- 共用資料：玩家識別、玩家庫存、取得紀錄、人物資料、人物成就歸屬、人物建立資格、收藏屋構造及訂單結果。
- 互動介面：人物建立／選擇／編輯、進階款與人物資格購買、初始提桶、收藏屋建造／修改及存放櫃。
- 遊戲邊界：提供入口條件及人物／道具存取，後續遊戲依賴此成果；本 MVP 不實作賽車、賽道、車輛效能或其他遊戲玩法。
- 現況查核（2026-09-08）：Phase 2 開始前 `docs/specs/`、`docs/bdd/`、`docs/tdd/`、`docs/alldonejobs/` 無文件包；本輪新增第一份模型 SPEC。`overview/` 目前只有目錄指引。已使用本機 `Blender 5.2.1 LTS` 在停用自動腳本的背景程序唯讀檢查 `blender/brickhigh.blend`，其物件只有 `Camera`、`Cube`（8 個頂點）與 `Light`；尚無可驗收的積木模型庫。`bootstrap_blender_mcp.py` 僅負責初始場景與 MCP 啟用。

## 已確認規劃

使用者於 2026-09-08 回覆「三項皆同意」，下列三項均成為本 MVP 的業務規則。保留 `PLAN-*` 編碼以維持既有追溯引用。

| 決策 ID | 實際功能影響 | 已確認方案 | 狀態 |
|---|---|---|---|
| `PLAN-001` | 完全不限制的隨機桶可能缺少可用建材，也可能讓限定組件由普通桶取得。 | 2026 片允許同款重複，抽取池排除特殊款；依收藏屋完成條件保證必要建材，其餘隨機，總量仍恰為 2026。抽樣方法在 SPEC 定義。 | 已確認，2026-09-08 |
| `PLAN-002` | 每個人物重用初次建立條件，但收藏屋與道具又涉及玩家共用，需確定是否重新建屋。 | 每次新人物建立皆享建立期半價與一桶 2026 片；收藏屋由玩家共用，已有收藏屋時新桶直接存入，不再要求重新建屋。此方案會讓每個額外人物增加玩家共用積木數量。 | 已確認，2026-09-08 |
| `PLAN-003` | 必須有可判斷的建屋完成條件，才能驗收遊戲入口解鎖。 | 至少有相連結構、地板、牆面、出入口及屋頂；檢查方式、尺寸及容許誤差由 SPEC 定義。此限制會影響可接受的自由造型。 | 已確認，2026-09-08 |

模型目錄暫不自行排除 `DUPLO`、`Technic`、人物零件、顏色與印刷版本，因本次僅明確排除停產。模型 SPEC 須提出具體系列範圍、目錄基準日及停產證據規則供確認，避免把短期缺貨或套裝停產直接推定為零件停產。
