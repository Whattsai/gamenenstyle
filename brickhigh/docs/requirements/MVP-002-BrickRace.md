# brickhigh 是一款享受樂高自由的3d畫面開放式自由地圖遊戲，運用擁有的樂高，參與各式各樣不同的遊戲

延續MVP-001成果，預計完成一款賽車遊戲，涵蓋以下模組需求：

專屬遊戲模組：未來會持續擴充其他遊戲專屬模組
1. 進入時如有多個人物，請玩家選擇該次要遊玩的人物，與成就有關
2. 須建立3張地圖供玩家選擇，初步以世界各舉辦F1的賽道來建立，未來應可持續增加
3. 車輛建置與管理：
- 初次進入時，發放24顆輪子，確保建立車輛必須要的積木組件與數量
- 進入時若沒有車輛，需請玩家從道具收藏屋用樂高建立專屬的車輛，才可選擇地圖開始遊戲
- 要有演算法可以判斷車輛建立結果的效能，不是隨便隨機產生的結果
- 後續可隨時改變車輛的積木組成，讓玩家持續調校車輛
- 預設給3個展示櫃存放多台專屬車輛，可以付費取得展示空間建立更多車輛
- 如果未來有其他遊戲或模組需要取得車輛，要可以跨模組存取已建立好的車輛使用

## 已確認的共用架構與畫面方向（2026-09-09）

使用者在合併評估 MVP-001 與本 MVP 的單機、引擎與畫面方案後回覆「同意 請繼續」。本節同步已同意方向，原始賽車需求完整保留；本 MVP 尚未執行正式化或 SDD 切分，本輪仍只修訂 `SPEC-001-BrickModelCatalog`。

- 延用 [MVP-001 的 `DEC-003`～`DEC-006`](MVP-001-V1Version.md)：Windows 原生單機、`Unity 6.3 LTS`、`URP`、`C#`，資料全在地端，安裝後可離線遊玩；玩家不需啟動 HTTP 或資料庫服務。
- 人物、庫存與車輛採同一程式內模組及本機存檔契約；三個預設展示櫃、後續展示空間購買與初始 24 顆輪子的發放須在賽車規格中驗收。購買沿用模擬付款與完整本機發放流程。
- 畫面以精緻塑膠積木玩具質感為方向，三張賽道保留原需求的 F1 賽道參考；搭建時注重清楚的接合預覽，駕駛時使用穩定追尾鏡頭，動態模糊與晃動可關閉。先以固定基準機上的 `1080p / 60 FPS` 為目標。
- 車輛性能由組裝資料計算：零件質量與位置影響重量／重心／慣量，輪徑／輪距／軸距與輪組配置影響駕駛參數，外形可採有說明依據的風阻近似。同一設計與同版規則產生相同性能參數，不要求不同平台的整場物理模擬逐位元一致。
- 編輯時保留逐片資料，行駛時以主要車身剛體與簡化複合碰撞體搭配獨立輪組；先驗證 `WheelCollider` 與代表車型。需用路緣／坡道測試其接地限制，模型外觀與行駛碰撞面可分別製作，避免每個積木凸點都引起車輪跳動。
- 正式鎖定模型／物理尺度前，驗證至少 2026 片代表積木場景、不同配置的自製車及含彎道／路緣／坡度的試驗賽道。這些是技術驗證，不取代三張正式賽道，也不表示已完成實測。

### 留待本 MVP 規劃的業務決策

車輛動力來源（統一基礎動力或由馬達零件決定）、合法輪組／車架條件、質量參數的量測或遊戲校準規則、三張具體賽道與遊戲尺度，尚未決定。初始發放 24 顆輪子保留原意，但不能直接推定所有輪胎／輪圈／車軸都互相相容，也不能假設只要有輪子就已能產生動力。
