# Docs 目錄指引

`docs/` 保存需求到實作驗收的可追溯文件。新子專案複製模板後，請以實際需求為基礎使用 `$perfect-plan` 產生文件，再由 `$well-done` 接手開發與驗收。

## 建議結構

| 目錄 | 用途 |
|---|---|
| `requirements/` | MVP 或高階需求文件 |
| `specs/` | SDD/SPEC 規格文件 |
| `bdd/` | BDD Feature 與 UX 場景 |
| `tdd/` | TDD 測試清單與實作交接依據 |
| `alldonejobs/` | 完成後的稽核、交接或結案紀錄 |

## 維護規則

- 不要在空白模板中預先放入假需求。
- 每個需求應有可追溯的 requirements、specs、bdd、tdd 文件鏈。
- 實作完成後，將測試結果、文件更新與剩餘限制寫回對應文件或結案紀錄。
- 不要提交密鑰、正式資料、私人帳號或不可公開的環境設定。
