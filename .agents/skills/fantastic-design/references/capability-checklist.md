# SD 流程能力完整性檢查

本文件供三個技能的維護與驗收使用。規則全文由 [planning-rules.md](planning-rules.md) 與 [document-contract.md](document-contract.md) 定義；每項能力須有具體規則、範本欄位與可觀察行為，不能只保留欄位名稱。情境 ID 見 [scenario-checks.md](scenario-checks.md)。

|---|---|---|---|

## 分工與恢復的維護查核

有分工授權時，以總覽分項表與檢查點記錄任務、責任、實際模型／effort、可寫資源、狀態、依賴及驗證，並提供一致的使用者進度視圖。未知資訊不捏造，實際啟動成功才標為執行中。並行數量依獨立性及協調成本決定，不強制啟動代理。

中斷後須查核恢復條件、實際檔案、有效成果及寫入者狀態；條件解除、續作啟動與驗收通過是不同事件。已取得的有效決策不重複詢問；不得把沉默視為同意、被動通知視為續作、續作成功視為驗收完成。

## 範本一致性查核

四份 SD 範本保留功能 ID、需求關聯、優先級、狀態與功能／故事／操作／技術／測試／依賴／文件結構。每份分項另具完整進度、Sprint、里程碑、關鍵指標、每日記錄、逐檔案設計、實際證據及續作資訊。

依 [步驟設計契約](step-design.md) 查核每個 I 的步驟集合、唯一責任及 F／V 映射；每步有具體輸入輸出、案例／斷言、工作目錄／命令、通過／停止與續作條件。從實際基準逐步桌面檢查，不允許用大型 Todo、模糊動詞或無結果判定的操作代替細部設計；final 合併後須重建順序與 ID 對照。

設計完成度、來源設計涵蓋率、實作驗證完成度分開；SD Todo 葉節點唯一計數，里程碑與矩陣不重複計數，零分母 N/A。來源 BDD／TDD 沿用自身慣例；跨包來源在全部必要成果及整合驗證成立後才能勾選。維護時同步核對固定資產與情境，不改動既有 SDD／BDD／TDD 範本。
