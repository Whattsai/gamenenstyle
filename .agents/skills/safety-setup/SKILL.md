# 安全防護設定

預設繁體中文，跟隨使用者語言。技能與品牌資料以目前專案 `.agents/skills/` 為基準。
安裝或修復一律依工具 `INSTALL.md` 使用 `scripts/install.py --project-root <目標專案>` 預覽，加 `--install` 才執行；不要只儲存本檔。

## 我的任務

1. 優先處理危險操作防護：強制刪除、Git 強制覆蓋、關機重開與磁碟破壞。
2. 用戶需要時，選用白名單減少例行工具確認；先說明放行範圍與風險。

## 執行流程

### Step 1：確認環境與可用設定

先辨識目前執行環境、版本與專案權限，查核其實際文件和既有設定。
確認是否支援拒絕規則、逐工具允許、路徑限制、規則優先序、重新載入及撤銷方法。
不要把某一工具的設定格式直接寫進另一環境，也不要預設能修改全域設定。
不支援的項目列為「未支援」；無法驗證的項目列為「待驗證」。文字規範不能冒稱為技術封鎖。

### Step 2：先給出具體防護方案並確認

列出實際設定位置、原有規則、建議增加的規則與套用範圍，讓用戶確認後才修改。
保留原有設定；格式錯誤先停止，不強行覆蓋。使用適合該格式的讀寫方式，避免破壞設定。

危險操作清單依實際 shell 與工具轉成受支援的規則：

- 強制／遞迴刪除：根目錄、家目錄、目前目錄及其萬用字元；含 `rm -rf`／`rm -fr`／`rm -Rf`、PowerShell 遞迴刪除及同等操作。
- Git：`reset --hard`、`push --force`／`push -f`、`branch -D`、`clean -f`。
- 系統：提權、`shutdown`、`reboot`、`diskutil erase`、`dd`、`mkfs` 及同等磁碟操作。

這些是要評估的操作類別，不是各環境都通用的可執行黑名單。不得為了驗證而真的執行破壞性命令。

### Step 3：驗收防護

依環境支援的唯讀解析、規則預覽或安全的匹配測試驗證，再重新讀取設定。
回報「已套用並驗證」「已寫入待重新載入／待驗證」「未支援」，列出設定位置與撤銷方法。
只宣稱有證據的保護，不保證列舉規則能涵蓋所有等價命令、所有工具或提示注入。

### Step 4（選用）：白名單／自動允許

防護盤點完成後，逐題詢問要不要設定自動允許，給三個選項：

- **A. 輕度（建議先用）**：指定的唯讀檔案、查詢與 Git 狀態操作。
- **B. 中度**：在 A 之上增加指定專案的品牌資料／草稿編輯，以及用戶選定的精確工具。
- **C. 自訂**：依用戶常被詢問的動作逐項選定，確認可限制的工具、參數與路徑。

只使用環境確實支援的精確規則；無法限制到所需範圍就說明並保留原設定，不猜最接近的語法。
不以 `mcp__*`、全部命令或跳過所有權限當成通用解法。白名單會擴大 AI 可直接操作的範圍，唯讀也可能讀到敏感內容。
套用前說明實際放行的行為與撤銷方式，取得用戶同意後寫入，再驗證。

## 發布確認與節流

工具允許設定只處理環境的執行權限，**不能取代** `.agents/skills/_brand/account-safety.md` 的內容確認。
發文、留言、私訊、群發、廣告上線與預算調整仍遵循原有確認閘門與節流。
平台預先設定的自動回覆規則也須先確認內容；不得把「少按工具允許」解讀成「可以自行公開發布」。
